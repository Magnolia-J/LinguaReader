# LinguaReader 云端同步 · 上手指南（Supabase）

> 代码已经写完并验证通过。你只需按下面的步骤“让云端表建起来 + 登录一次”，数据就会自动备份到云端。
> 预计总耗时：**5–10 分钟**（含一次 Supabase 控制台操作）。

---

## 前置确认（先看一下）

1. **本地服务在运行**：浏览器能打开 `http://localhost:3007/`，且能看到书籍和知识库。
   - 如果打不开，回到项目目录用 `node server.js` 重新启动（保持这个黑窗口开着）。
2. **云端配置（用户自填）**：本项目**不内置任何人的 Supabase**。请在桌面端「☁ 云同步」弹窗里填入**你自己的** Supabase 项目：
   - URL：形如 `https://your-project-ref.supabase.co`
   - Key：你的 publishable / anon key（公开安全，由行级安全 RLS 保护）
   - 配置只存在你本机浏览器，不会上传，也不会连到别人的项目。

---

## 第一步（最关键）：在 Supabase 建表

云端还需要一张数据表，代码才能往里写。你给的 Supabase 项目现在还没有这张表（我直连测试过，返回 404 = 表不存在，但项目和 key 都是有效的）。

1. 打开浏览器，访问 **https://supabase.com** → 登录你的账号。
2. 进入你自己的项目（项目名可能在左上角下拉里）。
3. 左侧菜单点 **SQL Editor（SQL 编辑器）** → 点 **New query（新建查询）**。
4. 打开本项目的文件 **`supabase/schema.sql`**（和本指南在同一文件夹），**全选复制**里面的全部内容，粘到 SQL Editor 里。
   - 内容大致是：建 `kb_store` 表 + 开启行级安全 + 写一条访问策略 + 授权 + 加索引。
5. 点右上角 **Run（运行）**。
6. 看到绿色 “Success” 或几条成功提示，即表示表建好了。
   - 验证：左侧菜单点 **Table Editor（表编辑器）**，应能看到 `kb_store` 表（字段：`user_id`、`payload`、`updated_at`）。

> 只需执行这一次。以后换设备、重装都不用再跑。

---

## 第二步（推荐）：关闭邮箱验证，省去收邮件这一步

Supabase 新项目默认开启“注册后必须验证邮箱才能登录”。如果不关，注册后会提示你去邮箱点验证链接，稍微麻烦。

- **想省事**：左侧菜单 **Authentication（认证）** → **Providers（提供商）** → 点 **Email** → 把 **Confirm email（确认邮箱）** 关掉 → **Save**。
  - 关掉后，注册完立刻就能登录并同步。
- **不想关**：保留默认即可，但注册后要去邮箱（含垃圾邮件）点验证链接，再回来点「登录」。

> 两种方式都能用，按你习惯选。

---

## 第三步：刷新本机页面，加载新代码

回到 `http://localhost:3007/` 这个页面，**刷新一下**（普通 F5 即可；本应用已设 no-cache，会自动拉最新 JS）。
- 刷新后，顶栏右侧应出现一个 **「☁ 云同步」** 按钮（在“阅读统计”“导出知识库”旁边）。

---

## 第四步：注册 / 登录云同步

1. 点顶栏的 **「☁ 云同步」** 按钮 → 弹出同步窗口。
2. 在窗口里填：
   - **邮箱**：你的邮箱（例如 `you@example.com`）
   - **密码**：至少 6 位（记好，这是你云端账号的密码）
3. 分两种情况：
   - **第一次用（还没有云端账号）**：点 **「注册新账号」**。
     - 若第二步关了邮箱验证 → 立刻提示“注册成功，已同步”，窗口切到“已登录”状态。
     - 若没关 → 提示“请到邮箱点击验证链接后再登录”，去邮箱点完链接，回来填同样邮箱密码点 **「登录」**。
   - **已有云端账号**：直接填邮箱密码点 **「登录」**。

---

## 第五步：确认同步成功

成功后会有这些可见信号：
- 顶栏按钮从「☁ 云同步」变成绿色的 **「☁ 已同步」**。
- 弹窗里显示“已登录：你的邮箱”。
- 屏幕底部弹绿色提示“✓ 登录成功，已与云端同步”。

**首次登录会发生什么**：你本地现有的全部数据（3 本书 + 20 条词汇/句型/批注 + 阅读进度）会被**自动推送到云端**。这是“备份到云”的动作，之后就不怕本机丢数据了。

**去云端核对（可选）**：Supabase 左侧 **Table Editor** → `kb_store` → 应能看到 **一行**数据，`payload` 字段里是一大段 JSON（你的全部知识库）。能看到即代表云端已存上。

---

## 第六步：多设备查看 / 换设备恢复

- 在**另一台设备**打开同一个应用（注意：应用是本地 Node 服务，另一台设备要能访问到它——同一台电脑换浏览器即可；手机需用局域网 IP 或把应用部署出去，那是另一个话题）。
- 打开页面 → 点「☁ 云同步」→ 用**同一个邮箱密码登录** → 自动从云端拉取数据，词汇/句型/批注/进度都会出现。
- 任意一端新增或修改，约 **4 秒**后自动上传；每 **60 秒**自动拉一次云端更新。

## 日常使用 & 注意事项

- **保持本地服务运行**：别关掉启动 `server.js` 的那个黑窗口；关了页面就读不到本机数据（有浏览器本地兜底，但不够全）。
- **自动同步是静默的**：你正常收藏、批注、阅读，后台会自动上传，不用手动点。想立刻同步可随时点「☁ 已同步」→「立即同步」。
- **多设备不互相覆盖**：数据按 id 合并，阅读时长取最大值；不会一端把另一端清空。
- **退出登录**：点弹窗里的「退出登录」只断开云端，本地数据原样保留；下次登录自动再同步。
- **换电脑/重装后**：只要用同一个 Supabase 账号登录，数据就能拉回来（前提是云端表已建、且之前同步过）。

## 常见问题排查

| 现象 | 原因 / 解决 |
|---|---|
| 点「☁ 云同步」没反应 / 一直提示“未配置 Supabase” | 检查 `js/supabase-config.js` 的 URL 和 KEY 是否完整（正常已填好）；确认 `index.html` 里的 Supabase CDN（`@supabase/supabase-js@2`）能加载（需联网）。 |
| 注册后登录提示 invalid login credentials | 邮箱还没验证。去邮箱点验证链接；或在第二步关掉 Confirm email 后重新注册。 |
| 弹“⚠ 云端同步失败：…表不存在 / relation not found” | 第一步的 `schema.sql` 没跑，或跑错项目了。回到 Supabase 跑一次建表 SQL。 |
| 同步一直失败，控制台报 “Supabase JS 未加载” | CDN 被网络拦截。换能访问 jsdelivr 的网络；或之后我把 Supabase JS 改成本地文件引入。 |
| 手机打不开应用页面 | 应用是本地服务，默认只在本机 `localhost`。手机访问需局域网 IP 或部署，单独处理。 |

## 安全说明（放心用）

- 用到的 key 是 **publishable / anon key**，本来就公开写在浏览器里，**不涉密**。
- 真正的安全靠 **行级安全（RLS）**：`schema.sql` 里写了策略 `auth.uid() = user_id`，别人读不到你的那一行。
- **千万不要**把 Supabase 的 **service_role key** 放到前端代码里（那个才有超级权限）。本项目只用了 anon key，符合规范。
